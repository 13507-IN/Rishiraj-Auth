Checking database

Use your own PostgreSQL database

This is a server-level setting. All workspaces on one Rishi Auth deployment use the same database, with workspace access checks. For a separate physical database, run your own deployment.

  1. Create an empty PostgreSQL database.
    Use a local PostgreSQL server or a hosted PostgreSQL service. Create a database user dedicated to Rishi Auth.
  2. Set the connection on your server.
    Place this in the server’s .env file. Replace the placeholders and use your provider’s required TLS settings. Never put it in browser code.
    DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require
  3. Prepare the tables.
    Back up existing data before changing databases. Run these commands from the project folder, with your intended database selected.
    npm ci
npm run build
npx prisma migrate deploy
npm start
  4. Check the connection.
    Open /health, then register a test account and check its record in your database. A health response alone does not test the complete sign-in flow.
Database migration guide ↗

Already have an application database?

Keep your application’s business data there. Your backend can verify a Rishi Auth access token with POST /auth/verify-token and store the returned user ID alongside its own records. Check valid and the expected workspace before granting access.

There is no automatic sync to another database. Password hashes, refresh tokens, and provider secrets should never be copied into your frontend.

Add the SDK to your website

Add your website’s exact origin to ALLOWED_ORIGINS on the server and restart it. Keep the SDK tokens in memory. Your backend must verify tokens before returning private data.


        
Before inviting real users
  1. Configure email delivery and test verification and password recovery.
  2. Test each connected provider with a test user in the provider’s developer console.
  3. For production, use HTTPS, strong secrets, Redis, and a backed-up database.
  4. Try sign-in, sign-out, and a revoked session from a second browser.
