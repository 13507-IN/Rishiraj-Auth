Quick Start

🚀 3-Step Integration

Add secure authentication to your HTML project in less than 2 minutes.

<!-- Include in the <head> of your page -->
<link rel="stylesheet" href="https://your-auth-server.com/sdk/rishiraj-auth-modal.css">

<!-- Include at the bottom of the <body> -->
<script src="https://your-auth-server.com/sdk/rishiraj-auth.js"></script>
const auth = new RishirajAuth({
  tenantId: "YOUR_TENANT_ID",
  environment: "DEVELOPMENT", // or "PRODUCTION"
  serverUrl: "https://your-auth-server.com",
  onLogin: (user, tokens) => {
    console.log("Logged in successfully:", user);
    // Token is stored, ready for backend calls!
  }
});
<button onclick="auth.showLoginModal()">Log In / Register</button>
SDK API

📦 Client SDK Reference

Comprehensive API documentation for the `RishirajAuth` class instance.

Class Constructor Options

Passed inside the configuration object when instantiating the class:

OptionTypeDefaultDescription
tenantIdstring (UUID)RequiredThe ID of the tenant you registered in the Developer Console.
environment"DEVELOPMENT" | "PRODUCTION""DEVELOPMENT"API behavior environment. Separates credentials, rate limits.
serverUrlstringwindow.location.originThe domain where the Rishiraj-Auth backend server is deployed (e.g. "https://your-auth-server.com").
onLoginfunction(user, tokens)undefinedCallback executed when login/sign-up succeeds.
onLogoutfunction()undefinedCallback executed when the user logs out.
onTokenRefreshfunction(tokens)undefinedCallback executed when credentials auto-refresh.

Available Methods

auth.showLoginModal()

Injects and opens a beautifully styled registration, login, and forgot password modal inside the page context.

auth.logout()

Logs the user out, revokes the refresh token on the server, clears stored session states, and fires onLogout.

auth.getUser()

Returns the current authenticated user's cached profile (UUID, email, name, avatar, isVerified, tenantId).

auth.getTokens()

Returns the current access token and refresh token object: { accessToken, refreshToken }.

Backend

🛡️ Express Middleware Protection

Protect your custom Express endpoints by validating API Keys cross-origin.

const authMiddleware = (requiredService = null) => async (req, res, next) => {
  const apiKey = req.headers['x-api-key'] || req.headers.authorization?.replace('Bearer ', '');
  if (!apiKey) {
    return res.status(401).json({ message: 'Missing API key' });
  }

  try {
    const response = await fetch('https://your-auth-server.com/api-keys/validate', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({ apiKey })
    });

    const data = await response.json();

    if (!response.ok || !data.valid) {
      return res.status(403).json({ message: 'Invalid or Revoked API key' });
    }

    if (requiredService && (!data.services || !data.services.includes(requiredService))) {
      return res.status(403).json({ message: 'Forbidden: required service scopes missing' });
    }

    // Attach details to request
    req.tenantId = data.tenantId;
    req.keyId = data.keyId;
    req.environment = data.environment;
    next();
  } catch (err) {
    return res.status(500).json({ message: 'Internal validation server error' });
  }
};

module.exports = authMiddleware;
const express = require('express');
const authMiddleware = require('./authMiddleware');
const app = express();

app.get('/api/analytics', authMiddleware('analytics'), (req, res) => {
  res.json({
    message: "Success!",
    tenantId: req.tenantId,
    environment: req.environment
  });
});
API

🔑 Token Verification API

Verify user access tokens from your backend without sharing JWT secrets. This is the recommended approach for third-party integrations.

Why this endpoint? Third-party backends should never need your JWT signing secret. Instead, call this endpoint to cryptographically verify any access token issued by Rishiraj-Auth.

Verifies an access token's signature, checks revocation status, and returns the associated user details.

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

Alternatively, send the token via the Authorization: Bearer <token> header.

{
  "valid": true,
  "user": {
    "userId": "a1b2c3d4-e5f6-...",
    "tenantId": "b046133d-24dd-...",
    "role": "user",
    "email": "developer@example.com",
    "name": "Rishiraj"
  },
  "expiresAt": "2026-08-26T12:30:00.000Z"
}
{
  "valid": false,
  "error": "Token has expired"
}

Note: This endpoint always returns HTTP 200. Use the valid field to determine token validity. This is intentional — a verification API should not use HTTP status codes for token validity.

const authMiddleware = async (req, res, next) => {
  const authHeader = req.headers.authorization || '';
  const token = authHeader.startsWith('Bearer ')
    ? authHeader.slice(7) : '';

  if (!token) {
    return res.status(401).json({ message: 'Missing token' });
  }

  try {
    const response = await fetch(
      'https://your-auth-server.com/auth/verify-token',
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ token })
      }
    );

    const data = await response.json();

    if (!data.valid) {
      return res.status(401).json({
        message: data.error || 'Invalid token'
      });
    }

    // Attach verified user to request
    req.user = data.user;
    next();
  } catch (err) {
    return res.status(500).json({
      message: 'Auth server unreachable'
    });
  }
};

module.exports = authMiddleware;
Config

⚙️ Dual Isolated Environments

How the segregated Development and Production layers behave.

🟢 Development

Used for staging and sandbox integration. Verbose logging is enabled. Rate limits are relaxed. Registered users are immediately active without forcing email validation.

🔵 Production

Strict production rules. Strict API limits are enforced. Every user registration is locked until they receive and enter their email confirmation tokens.

Frontend

🔌 Integration Framework Snippets

Quick start layouts for React, Next.js, and raw JavaScript.

import React, { useEffect, useState } from 'react';

export default function LoginButton() {
  const [authClient, setAuthClient] = useState(null);
  const [user, setUser] = useState(null);

  useEffect(() => {
    // Dynamic import to support SSR environments
    import('https://your-auth-server.com/sdk/rishiraj-auth.js').then(() => {
      const auth = new window.RishirajAuth({
        tenantId: "YOUR_TENANT_UUID",
        environment: "DEVELOPMENT",
        onLogin: (u) => setUser(u),
        onLogout: () => setUser(null)
      });
      setAuthClient(auth);
      setUser(auth.getUser());
    });
  }, []);

  if (user) {
    return (
      <div>
        <p>Hello, {user.email}</p>
        <button onClick={() => authClient.logout()}>Sign Out</button>
      </div>
    );
  }

  return (
    <button onClick={() => authClient?.showLoginModal()}>
      Sign In
    </button>
  );
}
Security

🔒 Security & Token Caching

Guidelines for storing secrets and managing tokens.

  • Keep Secret Keys Secure: Never hardcode API Keys or export them to frontend files or repositories. Always fetch API validation results through backend server endpoints.
  • Auto token rotation: The JavaScript SDK maintains an active silent token-refresh timer. Stale access tokens expire within 15 minutes and rotate automatically using stored secure HttpOnly/LocalStorage refresh tokens.
  • Session Management: Developers can monitor and revoke active device sessions instantly via the Developer Dashboard.
